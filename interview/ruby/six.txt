                            <div class="answer-section"><div class="answer-title"><i class="fas fa-comment-dots me-2 text-primary"></i>Answer:</div><div class="answer-content">puts, print, and p are output methods with different behaviors. In 2026: 1) puts - adds newline after output, 2) print - no newline added, 3) p - returns inspect output (debugging), 4) puts - calls to_s, 5) p - calls inspect, 6) puts - returns nil, 7) p - returns the object.                                                         <div class="example-section">
                                <div class="example-header"><i class="fas fa-code"></i><span>📝 Code Example</span></div>
                                <pre class="example-content language-ruby" tabindex="0"><code class="language-ruby">puts vs print vs p:
    
    1. puts (with newline)
       puts 'Hello'
       puts 'World'
       # Output:
       # Hello
       # World
    
    2. print (no newline)
       print 'Hello'
       print 'World'
       # Output: HelloWorld
    
    3. p (inspect - debugging)
       p 'Hello'
       # Output: \"Hello\" (with quotes)
       
       p [1, 2, 3]
       # Output: [1, 2, 3] (inspect format)
       
       user = { name: 'John', age: 30 }
       p user
       # Output: {:name=&gt;\"John\", :age=&gt;30}
    
    4. Comparison Table
       Method | Newline | Output | Return | Use Case
       ------|---------|--------|--------|---------
       puts | Yes | to_s | nil | Normal output
       print | No | to_s | nil | Same line output
       p | Yes | inspect | Object | Debugging
    
    5. Real-world Examples
       # puts with arrays
       puts [1, 2, 3]  # Each element on new line
       
       # p with arrays
       p [1, 2, 3]     # [1, 2, 3] (inspect)
       
       # puts with nil
       puts nil        # (blank line)
       
       # p with nil
       p nil           # nil
    
    6. Best Practices
       - Use puts for normal output
       - Use print for prompts
       - Use p for debugging
       - Use pp for pretty print</code></pre>

                            <div class="answer-section"><div class="answer-title"><i class="fas fa-comment-dots me-2 text-primary"></i>Answer:</div><div class="answer-content">Blocks, procs, and lambdas are ways to pass code in Ruby with different behaviors. In 2026: 1) Blocks - anonymous code, not objects, 2) Procs - objects, can be stored, 3) Lambdas - procs with different behavior, 4) Blocks - called with yield, 5) Procs - called with call, 6) Lambdas - check argument count, 7) Lambdas - return exits lambda only, 8) Procs - return exits method. Choose based on need for objects and argument checking.</div></div>
                                                        <div class="example-section">
                                <div class="example-header"><i class="fas fa-code"></i><span>📝 Code Example</span></div>
                                <pre class="example-content language-ruby" tabindex="0"><code class="language-ruby">Blocks, Procs, Lambdas:
    
    1. Blocks
       # Block with do/end
       5.times do |i|
           puts i
       end
        
       # Block with {}
       5.times { |i| puts i }
        
       # Block with yield
       def greet
           puts 'Before'
           yield if block_given?
           puts 'After'
       end
        
       greet { puts 'Hello' }
    
    2. Procs
       # Creating a proc
       my_proc = Proc.new { |name| puts 'Hello, #{name}' }
       
       # Short syntax
       my_proc = proc { |name| puts 'Hello, #{name}' }
       
       # Calling proc
       my_proc.call('John')
       my_proc['John']
       my_proc.('John')
       
       # Proc with return
       def test_proc
           p = Proc.new { return 'Proc return' }
           p.call
           'Method return'
       end
       puts test_proc  # Output: Proc return (exits method)
    
    3. Lambdas
       # Creating a lambda
       my_lambda = lambda { |name| puts 'Hello, #{name}' }
       
       # Short syntax
       my_lambda = -&gt;(name) { puts 'Hello, #{name}' }
       
       # Calling lambda
       my_lambda.call('John')
       my_lambda['John']
       my_lambda.('John')
       
       # Lambda with return
       def test_lambda
           l = lambda { return 'Lambda return' }
           l.call
           'Method return'
       end
       puts test_lambda  # Output: Method return (lambda returns to method)
    
    4. Comparison Table
       Feature | Block | Proc | Lambda
       --------|-------|------|--------
       Object | No | Yes | Yes
       Argument Check | No | No | Yes
       Return Behavior | Method exit | Method exit | Lambda exit
       Syntax | {} or do/end | Proc.new | lambda or -&gt;()
       Use Case | Iterators | Callbacks | Callbacks with checks
    
    5. Proc vs Lambda Example
       # Proc (loose argument checking)
       p = Proc.new { |x, y| puts x }
       p.call(1, 2, 3)  # OK (extra args ignored)
        
       # Lambda (strict argument checking)
       l = lambda { |x, y| puts x }
       l.call(1, 2)     # OK
       # l.call(1, 2, 3) # Error (wrong number of arguments)
    
    6. When to Use
       Block | Proc | Lambda
       ------|------|--------
       Simple iterators | Stored callbacks | Method-like behavior
       Each, map | Event handlers | Argument validation
       Yield | Configuration | Functional programming</code></pre>

                        <div class="question-body show" id="answer-4">
                            <div class="answer-section"><div class="answer-title"><i class="fas fa-comment-dots me-2 text-primary"></i>Answer:</div><div class="answer-content">Classes and modules are both containers for methods but with different purposes. In 2026: 1) Class - can be instantiated (objects), 2) Module - cannot be instantiated, 3) Class - single inheritance, 4) Module - multiple inclusion (mixins), 5) Class - has state (instance variables), 6) Module - no state (except class variables), 7) Class - can be subclassed, 8) Module - cannot be subclassed. Use classes for objects, modules for behavior sharing.</div></div>
                                                        <div class="example-section">
                                <div class="example-header"><i class="fas fa-code"></i><span>📝 Code Example</span></div>
                                <pre class="example-content language-ruby" tabindex="0"><code class="language-ruby">Class vs Module:
    
    1. Class Example
       class Person
           attr_accessor :name, :age
           
           def initialize(name, age)
               @name = name
               @age = age
           end
           
           def greet
               'Hello, I'm #{@name}'
           end
       end
        
       john = Person.new('John', 30)
       puts john.greet
    
    2. Module Example
       module Flyable
           def fly
               'Flying!'
           end
       end
        
       module Swimmable
           def swim
               'Swimming!'
           end
       end
        
       # Mixin modules
       class Duck
           include Flyable, Swimmable
           
           def quack
               'Quack!'
           end
       end
        
       duck = Duck.new
       puts duck.fly     # Flying!
       puts duck.swim    # Swimming!
       puts duck.quack   # Quack!
    
    3. Module as Namespace
       module Math
           PI = 3.14159
           
           def self.square(x)
               x * x
           end
       end
        
       puts Math::PI          # 3.14159
       puts Math.square(5)    # 25
    
    4. Comparison Table
       Feature | Class | Module
       --------|-------|-------
       Instantiation | Yes | No
       Inheritance | Single | Multiple (mixins)
       State | Yes | Limited
       Subclassing | Yes | No
       Methods | Instance &amp; Class | Instance &amp; Module
       Use Case | Objects | Behavior sharing
       Super | Yes | No
    
    5. Mixin Pattern
       module Loggable
           def log(message)
               puts \"[#{Time.now}] #{message}\"
           end
       end
        
       class User
           include Loggable
           
           def save
               log('User saved')
           end
       end
        
       user = User.new
       user.save  # [2024-...] User saved
    
    6. When to Use
       Class | Module
       ------|------
       Create objects | Share behavior
       Maintain state | Namespace
       Single inheritance | Multiple mixins
       Domain models | Utilities
       Business logic | Cross-cutting concerns</code></pre>

                        <div class="question-body show" id="answer-5">
                            <div class="answer-section"><div class="answer-title"><i class="fas fa-comment-dots me-2 text-primary"></i>Answer:</div><div class="answer-content">include and extend are used to add module methods to classes. In 2026: 1) include - adds instance methods, 2) extend - adds class methods, 3) include - methods available on instances, 4) extend - methods available on class, 5) include - can be mixed in, 6) extend - adds singleton methods, 7) include - used for mixins, 8) extend - used for class extensions. Use include for instance methods, extend for class methods.</div></div>
                                                        <div class="example-section">
                                <div class="example-header"><i class="fas fa-code"></i><span>📝 Code Example</span></div>
                                <pre class="example-content language-ruby" tabindex="0"><code class="language-ruby">include vs extend:
    
    1. include (Instance Methods)
       module Greeting
           def hello
               'Hello!'
           end
       end
        
       class Person
           include Greeting
       end
        
       person = Person.new
       puts person.hello  # Hello! (instance method)
    
    2. extend (Class Methods)
       module ClassMethods
           def create
               new
           end
       end
        
       class Person
           extend ClassMethods
       end
        
       person = Person.create  # Class method
       puts person.class      # Person
    
    3. include vs extend Example
       module Loggable
           def log(message)
               puts \"Log: #{message}\"
           end
       end
        
       class User
           include Loggable  # Instance methods
       end
        
       class Config
           extend Loggable   # Class methods
       end
        
       # include (instance)
       user = User.new
       user.log('User created')
        
       # extend (class)
       Config.log('Config loaded')
    
    4. include with self.included
       module Helper
           def self.included(base)
               base.extend(ClassMethods)
           end
           
           module ClassMethods
               def helper_method
                   'Class method from include'
               end
           end
           
           def instance_method
               'Instance method from include'
           end
       end
        
       class MyClass
           include Helper
       end
        
       MyClass.helper_method      # Class method
       MyClass.new.instance_method # Instance method
    
    5. Comparison Table
       Feature | include | extend
       --------|---------|--------
       Method Type | Instance | Class
       Target | Class instances | Class itself
       Usage | Mixins | Class extensions
       Singleton | No | Yes
       Common Use | Behavior | Utilities
    
    6. When to Use
       include | extend
       --------|--------
       Instance behavior | Class behavior
       Mixins | Class extensions
       Multiple inheritance | Singleton methods
       Shared functionality | Utilities</code></pre>

                            <div class="answer-section"><div class="answer-title"><i class="fas fa-comment-dots me-2 text-primary"></i>Answer:</div><div class="answer-content">Symbols and strings are both text representations but with different behaviors. In 2026: 1) Symbols - immutable, single instance, 2) Strings - mutable, new instance, 3) Symbols - memory efficient, 4) Strings - memory heavier, 5) Symbols - used for identifiers, 6) Strings - used for data, 7) Symbols - faster for comparison, 8) Strings - slower for comparison. Use symbols for identifiers, strings for data manipulation.</div></div>
                                                        <div class="example-section">
                                <div class="example-header"><i class="fas fa-code"></i><span>📝 Code Example</span></div>
                                <pre class="example-content language-ruby" tabindex="0"><code class="language-ruby">Symbols vs Strings:
    
    1. Symbols (Immutable)
       # Creating symbols
       :name
       :age
       :\"user name\"
        
       # Symbols are unique
       puts :name.object_id  # Same ID
       puts :name.object_id  # Same ID
    
    2. Strings (Mutable)
       # Creating strings
       'name'
       \"name\"
       %q[name]
        
       # Strings are unique
       puts 'name'.object_id  # Different ID
       puts 'name'.object_id  # Different ID
    
    3. Performance Comparison
       # Symbols (faster comparison)
       :name == :name  # Very fast
        
       # Strings (slower comparison)
       'name' == 'name'  # Slower
        
       # Memory usage
       1000.times { :name }  # One object
       1000.times { 'name' } # 1000 objects
    
    4. Usage Examples
       # Symbols as hash keys (preferred)
       user = { name: 'John', age: 30 }
        
       # Strings as hash keys (allowed but less efficient)
       user = { 'name' =&gt; 'John', 'age' =&gt; 30 }
        
       # Methods
       'Hello'.to_sym  # :Hello
       :hello.to_s      # 'hello'
    
    5. Comparison Table
       Feature | Symbol | String
       --------|--------|-------
       Mutability | Immutable | Mutable
       Identity | Single | Multiple
       Memory | Efficient | Heavier
       Comparison | Very fast | Slower
       Use Case | Identifiers | Data
       Garbage Collection | No | Yes
    
    6. When to Use
       Symbol | String
       ------|-------
       Hash keys | Text data
       Method names | User input
       Enum values | String manipulation
       Identifiers | Output text
       Constants | Dynamic text
    
    7. Best Practices
       - Use symbols for hash keys
       - Use symbols for enum values
       - Use strings for text manipulation
       - Use string interpolation
       - Avoid string keys in hashes</code></pre>

               @name = name

           scope :active, -&gt; { where(active: true) }

           extend ActiveSupport::Concern

               Rails.logger.info '#{self.class} created'

       class User &lt; ApplicationRecord
